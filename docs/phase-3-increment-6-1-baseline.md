## Trace and bottlenecks

| Stage | Observed limit | Classification / intended fix |
| --- | --- | --- |
| Discovery | Many Fandom references; robots unavailable. Official chapter reader supplies an HTML shell. Some TLS failures. | Source-access limits; no bypass or fabricated manga text |
| Eligibility / archive | Four documents are not four independent narrative witnesses. Sparse reference metadata and an out-of-bound volume summary do not corroborate actions. | Acquire selective, chapter/arc-scoped independent review prose; retain authority and continuity distinctions |
| Ranking / retrieval | Name overlap and publisher authority outweigh original medium, substantive story evidence and repeated-use cost. | Explain medium/richness/novelty ranking without granting access |
| Connected evidence | Only same-section neighbors form a bundle; additional sources are considered by verification but are not attached as corroborating claim evidence. | Attach only independently eligible literal support for the identical bound assertion, never a mere name mention |
| Extraction | Connected candidate deduplication uses entity name/type, retaining only the first assertion. Atomic vocabulary rejects present-tense actions such as `saves` and `gives`. | Preserve separate assertions; extend tested literal grammar while retaining modality/direction/semantic checks |
| Identity | Legacy candidates see unrelated same-type records, inviting spurious semantic matches that deterministic alias checks then reject. | Limit proposals to grounded name/alias matches; preserve ambiguous names and sensitive identities |
| Verification | Legacy per-claim boolean classification is unreliable. Connected mode already offers per-atom compatible batches and verification reserve. | Reuse the existing connected path; reject deterministic failures before inference, retain negative verdicts |
| Permissions | Atomic verification's public-content flag checks the anchor bundle but omits related-source context in its prompt. | Check every included bundle before any cloud inference |
| Frontier | Priority mostly counts objective word overlap; expected value/cost remain defaults. Resolved leads can re-enter the planner's second lead-ID selection. | Favor missing connections and available evidence, discount repeated unresolved attempts, exclude resolved questions from work selection |
| Reader | Cache/dependency propagation fixed in 6.0; one validated location and partial arc exist. | Validate actual new graph/prose/API/browser propagation; no redesign |
