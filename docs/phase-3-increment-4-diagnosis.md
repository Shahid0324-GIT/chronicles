# Increment 4 diagnosis before implementation

Inspected the actual router, LangChain adapter, worker, typed workflow state, source acquisition, event frames, identity resolver, publication checks, narrative builder, Zustand state, frontend provider and Increment 3 live audit before editing implementation.

- The router retries invalid outputs with exactly the same system/prompt/schema. It records a generic invalid-output code, discarding which field failed. Provider errors and validation exhaustion converge on `no_provider_succeeded`. The prior jobs made 82 attempts including a downstream retry, then 46 on a fresh run; invalid identity outputs accounted for 12 and eight attempts respectively.
- There is a per-call attempt limit and provider semaphore, but no persisted job-wide/stage call limit or wall-clock execution deadline. A restarted worker's in-memory usage cannot alone enforce a job budget. Each candidate can trigger identity and verification calls, including repeatedly invalid requests.
- Event frames already distinguish actual/intended/hypothetical/uncertain and participant roles after the last live correction. They do not cover denied/reported events or opponents. A reported assertion needs corroboration rather than being silently relabeled actual. The prior beneficiary false positive remains explicitly reversed; it is not a successful autonomous correction.
- Indexed identity schemas require a target for SAME/DIFFERENT, but prompt/schema agreement and safe validation diagnostics are absent. Descriptive event identity remains model-assisted; exact source anchors and scoped aliases can safely prevent repeated matches without asking the model to rediscover deterministic evidence. Source co-occurrence alone is insufficient.
- The workflow persists end-of-node snapshots, not stage starts/durations. Individual provider calls are archived, but the job API has no concise aggregate telemetry or accepted-discovery summary. The worker remains independent of HTTP clients.
- `LocalNarrativeDataProvider` is the only provider. `StoryCanvas` always labels content curated. `eventRegion` traverses all canonical edges, so switching only catalog data could silently mix generated and curated associations.
- `loadNarrative` resolves against its pre-request graph snapshot and does not reconcile a selected step by stable ID after refresh. Existing graph refresh methods reset continuity/selection. A generated catalog referencing newly published nodes must arrive with a refreshed graph without resetting exploration state.
- The existing illustrated spine, event investigation, branches and source notes can render the same catalog shape. No redesign is needed. A same-origin Next route can proxy a deliberately limited set of backend reads/job creation, keeping the backend base URL server-only. Bounded status polling is simpler than adding SSE to the independent worker in this increment.

Preserve strict evidence, continuity, retraction and source-family gates. Changes will not manufacture location, chronology or causal edges to fill panels. Real UI/model verification and repeat results will be reported separately from synthetic tests.
