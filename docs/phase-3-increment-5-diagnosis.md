# Increment 5: diagnosis and implementation architecture

Inspected the actual narrative builder/repository, canonical publication/evidence contracts, workflow, provider budgets, source registry, frontend provider/state and Increment 4 verification before implementation.

The builder copies `payload.name` and `payload.description` into titles and bodies. These are extraction anchors, often Japanese verbs or full source sentences. A sorted first assertion is not an editorial summary. Same-sentence actions are not organized into an encounter. Source-episode bounds become representative milestones while other events remain unordered; this does not establish exact reveal order. Character/lore projections lack a shared entry structure, and successful narrative GETs repeatedly reconstruct rather than reuse independently versioned prose. Unknown source positions must remain excluded from bounded reads. Existing sensitive-identity exclusions and accepted-publication checks must survive.

Three distinct layers will be maintained: canonical graph/archive facts; deterministic scoped organization and reusable encyclopedia contracts; independently cached English presentation with grounding checks. Shared UUIDs, explicit edges, source references and source context connect entries and milestones. Grouping requires shared source context and excludes ambiguous repeated attempts/routes; it never creates chronology or causality.

One additive presentation-artifact table will retain resource ID, boundary, knowledge/evidence fingerprints, language, policy, provider metadata, timestamp and validation status. Existing graph types remain; category/section/epistemic metadata will represent documents, lore and other entry forms without a table per subtype. Theories stay sourced noncanonical archive claims, separate from operational verification decisions.

Composition will use the existing privacy-aware router and budgets, followed by deterministic reference/state/relationship/language checks and a targeted source-entailment assessment. Unchecked translation will not become reader prose. Read APIs will not generate text. Rebuilds can run through the independent worker without repeating acquisition, extraction or publication. Minimal frontend additions will use the existing provider, inspection and return-to-journey state rather than create a new navigation system.
