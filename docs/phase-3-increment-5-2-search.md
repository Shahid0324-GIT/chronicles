# Increment 5.2 search checkpoint

Actual SearXNG searches returned 25/25/26 results for original-source references, Emilia/Puck relationships and capital/insignia lore, and 23 results for an Elden Ring query. The existing adapter returned five URLs; the existing discovery service persisted three new navigation references. [Captured metadata and real provider probe](phase-3-increment-5-2-search.json). This is live search, not synthetic testing or a complete research demonstration.

Run `./tools/start-search.ps1` from PowerShell after installing root Python dependencies. It creates an ignored local random `SEARXNG_SECRET` if absent, sets `SEARXNG_BASE_URL=http://127.0.0.1:8080`, and starts the existing PostgreSQL volume and pinned official SearXNG image. No database reset occurs. Restart the API/worker after configuration changes. Inspect with `docker compose ps`; health checks use `/healthz`. Search with `/search?q=...&format=json`.

The service binds only 127.0.0.1. JSON is enabled in `infra/searxng/settings.yml`. The private instance has no public bot-limiter/Valkey service; the existing adapter serializes and paces research queries (configurable timeout and minimum interval), caps response bytes/results and rejects unsafe URLs. Search discovery is metadata, never ingestion permission. Explicit registered path rules can admit discovered public pages under their existing continuity, selections and permission basis. Rules are not fetched as documents. Unmatched references remain navigation-only. Unknown websites, copyrighted books and wiki visibility do not automatically authorize ingestion.

DuckDuckGo reported CAPTCHA and Brave later reported a rate suspension. No CAPTCHA or access restrictions were bypassed. The service reports upstream failures separately from an empty result set. Fandom robots retrieval was unavailable; direct Wikipedia retrieval failed TLS validation (the checked certificate was expired) and a separately verified HTTP client received 403. Verification was not disabled and no proxy was used.

The real Groq connectivity probe initially fell back because the health check matched a display name. Matching Groq `id` fixes it: configured `openai/gpt-oss-120b` returned actual structured output using 345 reported tokens through the primary credential. The probe content was owned synthetic text, not research evidence and not the later dossier benchmark. No key was printed, renamed or rotated. The user explicitly approved only a small public evidence dossier for the subsequent cloud comparison; other source flags/defaults are preserved.

Setup references: [official container documentation](https://docs.searxng.org/admin/installation-docker), [settings documentation](https://docs.searxng.org/admin/settings/settings.html). Source policy, evidence validation and the existing frontend are retained. End-to-end focused research and same-evidence model comparison remain to be completed after this checkpoint.
